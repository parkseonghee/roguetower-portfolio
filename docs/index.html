Overview

🎮프로젝트 개요

층마다 무작위로 생성되는 방에서 몬스터를 전멸시키고, 그 보상으로 얻은 아이템과 골드로 캐릭터를 강화하며 탑을 올라가는 2D 탑다운 로그라이크입니다. 층을 넘어가도 인벤토리와 스탯은 유지되고, 런이 끝나도 영구 성장 수치는 PlayerPrefs에 저장되어 다음 런에 반영됩니다.

My Role

🙋담당 범위

팀 프로젝트에서 제가 맡은 영역은 재화 획득 루프와 게임 진행 루프 두 축입니다. 플레이어 컨트롤·공격·몬스터 AI·스탯 UI는 팀원이 담당한 영역입니다.

💰재화 획득 루프

  • 아이템 데이터 테이블 설계 및 런타임 로딩 (CSV → Dictionary)
  • 티어 기반 아이템 확률 추첨 로직
  • 인벤토리·장비 시스템 (드래그&드롭, 슬롯 검증, 스탯 합산)
  • 씬 전환 간 인벤토리 데이터 이관
  • 아이템 상세 정보 툴팁 UI
  • 상점(구매) / 상자(선택 보상) 상호작용

🗺️게임 진행 루프

  • 층 진행 및 맵 생성
  • 런타임 NavMesh 베이크
  • 스폰 포인트 기반 몬스터 생성
  • 문(Door) 개방 조건 판정
  • 페이드 기반 씬 전환
  • 영구 성장 수치 저장/로드

Systems

⚙️시스템 상세

각 시스템의 설계 의도와 구현 방식입니다. 전체 코드와 자세한 설명은 저장소 README에 정리해 두었습니다.

📋아이템 데이터베이스

MySQL에서 관리하는 아이템 테이블을 CSV로 내보내 TextAsset으로 로드합니다. 14개 컬럼을 ItemData에 1:1 매핑하고 Dictionary에 담아 ID 기반 O(1) 조회. 싱글톤 + DontDestroyOnLoad로 씬이 바뀌어도 한 번만 로드합니다.

🎲티어 확률 추첨

상점과 상자가 같은 확률표를 쓰도록 추첨 로직을 ItemDatabase로 모았습니다. 누적 구간 판정으로 확률 총합 100%를 보장하고, 해당 티어 아이템이 없으면 전체 풀에서 대체 지급합니다.

🎒인벤토리 / 장비

슬롯은 입력·표현만, 매니저는 판정·데이터 변경만 담당하도록 분리했습니다. 드래그&드롭 스왑, 슬롯 타입 양방향 검증, 우클릭 퀵 장착, 장착 스탯 합산 후 최대 체력 증감분 보정까지 처리합니다.

☁️씬 간 인벤토리 이관

UI를 DontDestroyOnLoad로 유지하면 레이아웃이 깨져, 매니저·UI는 씬과 함께 파괴하고 아이템 ID만 static 저장소에 백업하는 방식으로 분리했습니다. OnDestroy에 저장, Start에 복원 후 스탯을 재계산합니다.

🏪상점

F키 개폐, 입장 시 1회만 품목을 추첨해 리롤 어뷰징 차단. 연타 중복 구매를 2중 방어로 막고, 인벤토리가 가득 차 획득에 실패하면 골드를 전액 환불합니다.

🎁보상 상자

3개 후보 중 1개를 선택하는 로그라이크식 보상. 중복 방지 재추첨에 failSafe 카운터를 둬 아이템 풀이 작을 때 무한 루프에 빠지지 않도록 방어했습니다.

🌊웨이브 · 맵 생성

맵 생성 → NavMesh 베이크 → 몬스터 스폰 순서를 코루틴으로 고정했습니다. 같은 프레임에 베이크하면 Tilemap 콜라이더가 갱신되지 않아, WaitForEndOfFrame() 후 베이크하고 완료 뒤에야 스폰합니다.

🚪문 · 씬 전환

미클리어 상태의 문은 콜라이더와 스프라이트를 함께 꺼 보이지도 통과되지도 않게 처리. 페이드는 timeScale = 0에서도 동작하도록 unscaledDeltaTime을 사용합니다.

🏗️층 진행 · BGM

1~9층은 맵 프리팹 랜덤, 10층은 보스맵 고정. BGM은 같은 클립이면 교체하지 않고 유지해 층을 넘어가도 음악이 끊기지 않고, 10층 진입 순간에만 보스 BGM으로 전환됩니다.

🔐전역 UI 잠금

인벤토리·상점·상자가 동시에 열려 입력과 timeScale이 충돌하던 문제를 Player.isAnyUIOpen 전역 플래그로 통일했습니다. 문 상호작용도 이 플래그를 확인합니다.

Troubleshooting

🛠️트러블슈팅

개발 중 실제로 겪은 문제와 해결 과정입니다.

☁️

층 이동 시 획득한 아이템이 전부 사라짐

씬 전환으로 인벤토리 매니저와 UI가 파괴되는 것이 원인. → static 저장소에 아이템 ID만 백업하고 새 씬에서 복원하도록 분리.

🖱️

상점 버튼 연타로 같은 아이템이 중복 구매됨

결제 처리 후에도 같은 인덱스가 계속 유효했던 것이 원인. → 결제 성공 즉시 ID를 비우고 버튼을 비활성화하는 2중 방어.

💰

인벤토리가 가득 찬 상태로 구매하면 골드만 소진

결제 후 AddItem 실패를 처리하지 않았던 것이 원인. → 실패 시 전액 환불 + 안내 문구 출력.

🧭

몬스터가 벽을 통과하거나 길을 찾지 못함

맵 생성과 같은 프레임에 NavMesh를 베이크해 Tilemap 콜라이더가 갱신되지 않았던 것이 원인. → WaitForEndOfFrame 후 베이크, 완료 뒤 스폰.

⏸️

timeScale = 0에서 UI 연출과 페이드가 멈춤

deltaTime이 0이 되는 것이 원인. → unscaledDeltaTime / WaitForSecondsRealtime으로 교체.

🔐

UI가 중첩되어 입력과 시간 흐름이 충돌

UI마다 개별적으로 timeScale을 제어했던 것이 원인. → Player.isAnyUIOpen 전역 플래그로 통일.

👻

빈 슬롯을 드래그해도 고스트 아이콘이 생성됨

빈 슬롯도 드래그 이벤트를 수신한 것이 원인. → eventData.pointerDrag = null로 이벤트 차단.

♾️

아이템 풀이 작을 때 중복 방지 루프가 멈추지 않음

조건 충족까지 무조건 재추첨한 것이 원인. → failSafe 카운터(50회)로 탈출 보장.

Principles

💡설계 시 중점을 둔 부분

📊데이터와 로직의 분리

아이템·몬스터·플레이어 수치를 CSV/JSON으로 빼내, 코드 수정 없이 밸런싱이 가능한 구조.

🧩책임 분리

슬롯은 입력·표현만, 매니저는 판정·데이터 변경만 담당.

🎲확률표 단일화

상점과 상자가 같은 추첨 함수를 사용해 밸런스 불일치를 방지.

🛡️방어적 프로그래밍

데이터 결손 시 경고 로그, 무한 루프 탈출 카운터 — 잘못된 데이터가 들어와도 게임이 멈추지 않게.

🧱프리팹 환경 대응

씬에 없을 수 있는 참조는 인스펙터 고정 대신 충돌·호출 시점에 동적으로 탐색.

🕹️플레이 경험 보호

리롤 어뷰징 차단, 골드 환불, 암전 후 맵 이동 등 플레이어가 손해 보거나 어색함을 느끼지 않도록 처리.
